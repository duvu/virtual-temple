## Change Content Summary

- Lifecycle operations serialize through a lock and validate process identity before status or stop actions.
- Startup builds the workspace, waits for `/healthz`, records a PID, and uses `nohup` so the API tolerates a terminal hangup in normal Linux shell use.
- Demo state is in-memory and is lost when the API stops.
- Scripts resolve the repository root from their own location and accept `PORT` or `VTL_BASE_URL`.

## Affected Flows

- Developer install, build, typecheck/test, and foreground development workflows.

## Impact And Risks

- Process-control scripts require Linux `/proc`, Bash 4.4+, and `flock`; health probes require `curl`.
- The execution runner used for this task terminates child processes at the end of each command invocation. A detached API therefore could not be checked across separate tool invocations; the full lifecycle was verified in one shell instead.
- The demo channel/runtime is ephemeral and not persisted.
